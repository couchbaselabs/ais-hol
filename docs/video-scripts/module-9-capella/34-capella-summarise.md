# Capella AI Summarisation

**Module:** Capella AI Functions | **Level:** Advanced
**Runtime:** ~6 min | **Tab:** `capella-summarise`

---

## Hook

Every AI integration we've built so far follows the same pattern: application code calls an LLM API, gets a response, does something with it. What if the LLM call happened inside the database instead? Couchbase Capella AI Functions expose LLM capabilities as SQL++ built-in functions — you write a SELECT statement and get an AI-generated summary back. No extra HTTP call, no SDK integration, no application code to deploy.

---

## Concept

**Capella AI Functions** are LLM capabilities exposed as SQL++ built-in functions in the Couchbase query engine. `default:ai_summary()` is one of them — it takes text and returns a summary, all within a SQL++ query.

```sql
SELECT default:ai_summary({"text": $text, "max_words": 100}) AS result
```

That's it. The Capella query engine calls the configured LLM internally. The application issues a SQL++ query and gets a summary back in the result row.

Why does this matter?

**Simplicity**: no LLM SDK in your application, no API key management in application code, no extra HTTP call. The LLM provider and credentials are configured once in Capella.

**Bulk enrichment**: you can run `ai_summary()` over an entire collection in one query — summarise every document at query time without an application loop.

**Consistency**: the same LLM configuration applies to all queries. No risk of different parts of the application using different models or temperatures.

**Limitations**: requires the Summarization AI Function to be enabled on the Capella cluster, and the `query_external_access` role on the database user. Not available on self-managed Couchbase Server — Capella only.

## Code Deep-Dive

The backend issues a SQL++ query — no LLM SDK call:

```python
sql = """
    SELECT default:ai_summary({
        "text":        $text,
        "max_words":   $max_words,
        "temperature": 0.3
    }) AS result
"""
rows = list(
    cluster.query(
        sql,
        QueryOptions(named_parameters={"text": body.text, "max_words": body.max_words}),
    ).rows()
)
summary = rows[0]["result"][0]["response"]
# The LLM call happens inside Couchbase — no openai.chat.completions here
```

The same function is used for conversation history summarisation in the RAG pipeline tab:

```python
async def summarize_conversation(session_id: str, max_words: int = 150) -> str:
    history = await get_conversation_history(session_id)
    text = "\n".join(
        f"{'User' if m['role'] == 'user' else 'Assistant'}: {m['content']}"
        for m in history
    )
    sql = """
        SELECT default:ai_summary({
            "text":      $text,
            "max_words": $max_words,
            "temperature": 0.3
        }) AS summary
    """
    try:
        rows = list(cluster.query(sql, ...).rows())
        return rows[0]["summary"][0]["response"]
    except Exception:
        # Falls back to raw history if AI Functions are not enabled
        return format_conversation_history(history)
```

The `try/except` fallback is important for portability — if the cluster doesn't have AI Functions enabled, the application falls back to raw history rather than failing.

For bulk enrichment, the same function works over a collection:

```sql
-- Summarise every document in a collection at query time
SELECT d.id, d.title,
       default:ai_summary({"text": d.content, "max_words": 100}) AS summary
FROM `bucket`.`scope`.documents AS d
WHERE d.summary IS MISSING
LIMIT 100
```

## Key Takeaways

- `default:ai_summary()` is a SQL++ built-in that runs LLM summarisation inside the Couchbase query engine.
- No LLM SDK in application code — the LLM provider is configured once in Capella.
- Works for single documents and bulk enrichment over entire collections.
- Requires the Summarization AI Function enabled on the cluster and `query_external_access` role.
- Capella only — not available on self-managed Couchbase Server.
