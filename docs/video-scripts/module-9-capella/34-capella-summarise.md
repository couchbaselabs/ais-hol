# Capella AI Summarisation

**Module:** Capella AI Functions | **Level:** Advanced
**Runtime:** ~6 min | **Tab:** `capella-summarise`

---

## Hook

> 🎬 **SHOW:** Capella AI Summarisation tab open, text input area visible, max_words slider, and a response area showing "source: capella_ai_summary" badge (empty).

Every AI integration we've built so far follows the same pattern: application code calls an LLM API, gets a response, does something with it. What if the LLM call happened inside the database instead? Couchbase Capella AI Functions expose LLM capabilities as SQL++ built-in functions — you write a SELECT statement and get an AI-generated summary back. No extra HTTP call, no SDK integration, no application code to deploy.

---

## Concept

> 🎬 **SHOW:** Slide — two architecture diagrams side by side. Left: "Standard approach" — app → OpenAI API → app → Couchbase. Right: "Capella AI Functions" — app → Couchbase (SQL++ with ai_summary()) → result. The right side has fewer arrows.

**Capella AI Functions** are LLM capabilities exposed as SQL++ built-in functions in the Couchbase query engine. `default:ai_summary()` takes text and returns a summary, all within a SQL++ query.

```sql
SELECT default:ai_summary({"text": $text, "max_words": 100}) AS result
```

> 🎬 **SHOW:** Slide — three benefits: "Simplicity" (no LLM SDK in app code), "Bulk enrichment" (run over entire collections in one query), "Consistency" (one LLM config for all queries).

Why does this matter? No LLM SDK in your application, no API key management in application code, and bulk enrichment over entire collections is a single SQL++ query.

> 🎬 **SHOW:** Slide — requirements: "Summarization AI Function enabled on the Capella cluster" and "`query_external_access` role on the database user". Plus: "Capella only — not available on self-managed Couchbase Server."

Requirements: the Summarization AI Function must be enabled on the Capella cluster, and the database user needs the `query_external_access` role.

## Code Deep-Dive

> 🎬 **SHOW:** Open `backend/main.py`, scrolled to the Capella summarise endpoint. Highlight the SQL++ query — specifically `default:ai_summary()`. Point out there is no `client.chat.completions.create` call anywhere in this function.

The backend issues a SQL++ query — no LLM SDK call:

```python
sql = """
    SELECT default:ai_summary({
        "text":        $text,
        "max_words":   $max_words,
        "temperature": 0.3
    }) AS result
"""
rows = list(
    cluster.query(
        sql,
        QueryOptions(named_parameters={"text": body.text, "max_words": body.max_words}),
    ).rows()
)
summary = rows[0]["result"][0]["response"]
# The LLM call happens inside Couchbase — no openai.chat.completions here
```

> 🎬 **SHOW:** Highlight the comment "The LLM call happens inside Couchbase". Then scroll to the `summarize_conversation` function used in the RAG pipeline tab — show the same pattern.

The same function is used for conversation history summarisation in the RAG pipeline tab — the pattern is consistent across the application.

> 🎬 **SHOW:** Show the bulk enrichment SQL on a slide or in a code comment.

For bulk enrichment, the same function works over a collection:

```sql
-- Summarise every document in a collection at query time
SELECT d.id, d.title,
       default:ai_summary({"text": d.content, "max_words": 100}) AS summary
FROM `bucket`.`scope`.documents AS d
WHERE d.summary IS MISSING
LIMIT 100
```

> 🎬 **SHOW:** Highlight `WHERE d.summary IS MISSING` — this is an incremental enrichment pattern, only processing documents that haven't been summarised yet.

`WHERE d.summary IS MISSING` is an incremental enrichment pattern — only processing documents that haven't been summarised yet.

## Key Takeaways

> 🎬 **SHOW:** Return to the tab with a completed summary — the "source: capella_ai_summary" badge visible, summary text below it.

- `default:ai_summary()` is a SQL++ built-in that runs LLM summarisation inside the Couchbase query engine.
- No LLM SDK in application code — the LLM provider is configured once in Capella.
- Works for single documents and bulk enrichment over entire collections.
- Requires the Summarization AI Function enabled on the cluster and `query_external_access` role.
- Capella only — not available on self-managed Couchbase Server.
